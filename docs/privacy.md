# AdCalm 隐私说明

适用于 v0.1.1-beta.1，更新于 2026-10-06。本文说明应用实际处理的数据、可选诊断和用户分享行为。

## 本机处理

核心识别在设备本机完成：无障碍服务读取窗口节点，必要时使用 Android 截图能力与打包在应用内的 OCR 模型。所选应用、功能开关、操作记录、隔离索引和诊断文件存于设备中，不通过 AdCalm 服务器处理界面内容。

| 数据 | 何时产生 | 用途与范围 |
|---|---|---|
| 应用列表与使用情况 | 浏览应用管理、配置使用情况访问后 | 选择处理范围、本机推荐、保护名单和误跳判定。 |
| 观察日志 | 服务运行并记录识别结果时 | 新记录默认只含应用包名、时间、判定、点击方式和数值候选摘要。纯观察仍会产生日志；升级遗留的旧日志可能含候选原文。 |
| 完整节点树与截图 | 明确开启完整诊断后 | 仅记录所选应用，仍可能包含文字、账号、聊天、通知与其他私人界面内容。原始文件留在本机。 |
| 下载文件与隔离索引 | 用户启用下载处置或手动扫描后 | 判定候选、隔离、恢复及用户确认删除；文件路径和名称可能带有私人信息。 |
| 分享摘要或导出文件 | 用户主动导出并选择分享后 | 默认导出脱敏摘要，接收应用与 GitHub 等平台按各自规则处理。 |

## 诊断由用户明确开启

完整诊断默认关闭，开启前显示数据范围提示。它与纯观察是独立设置：观察表示不执行自动操作，不表示不读取或记录界面。

排查时短时开启，复现后关闭。原始日志、节点树和截图用于本机诊断，不直接作为公开反馈附件。新旧日志导出均经过同一字段白名单，无法解析的旧行跳过，不回退复制原文。

脱敏摘要保留时间、判定、模式、点击方式、屏幕尺寸、候选评分与坐标等数值信息；包名换成每次导出独立分配的 `app_1` 等代号，不导出映射表。摘要不含应用原包名、活动名、资源 ID、屏幕原文、完整节点树、截图或评分原因中的自由文本。时间与设备尺寸等元数据仍可能反映使用情况，分享前应检查是否适合公开。

## 留存与删除

- 观察日志按大小轮转，最多保留当前文件与上一份，每份上限约 16 MB；轮转会覆盖更旧的一份。
- 诊断截图最多保留最近 40 张，新的截图可能替换旧记录。
- 隔离文件持续保留，直到用户恢复或逐项确认永久删除；应用不再按时间自动删除。永久删除后不可恢复。
- “清空日志”删除应用保留的观察日志、诊断截图与应用生成的本机导出文件；自行另存或已分享的副本仍需用户管理。
- Android 的清除应用数据或卸载会清除应用私有记录，也可能使隔离文件无法恢复。操作前恢复需要保留的文件，并自行管理已分享或另存的副本。

## 权限与第三方页面

无障碍、使用情况、通知、文件访问及 Shizuku 的用途见[使用指南](guides/使用指南.md)。授权后仍需按功能确认，增强操作默认关闭；可在应用及系统设置中关闭相关开关或撤销权限。

AdCalm 的 Shizuku 获取入口仅通过外部浏览器打开[官方下载页](https://shizuku.rikka.app/download/)，不内置第三方镜像下载、安装器或 APK 安装权限。浏览器、下载站点和系统安装器可能处理网络与安装信息，其数据处理由对应产品决定。

用户主动在 GitHub 提交 Issue 或分享附件时，内容通常公开可见。优先提供版本、机型与系统版本、复现步骤、模式及开关状态；无需提供设备序列号、IMEI、联系方式、完整应用清单或原始诊断目录。
