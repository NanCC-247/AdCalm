# AdCalm 使用指南

适用于 **v0.1.1-beta.1**。这是公开测试版本，正式签名表示构建采用发布签名，兼容性和识别效果仍需测试。功能边界见[安全使用说明](安全使用说明.md)，数据处理见[隐私说明](../privacy.md)。

## 下载与安装

1. 打开 [v0.1.1-beta.1 Release](https://github.com/NanCC-247/AdCalm/releases/tag/v0.1.1-beta.1)，展开 **Assets**。
2. 下载 `AdCalm-v0.1.1-beta.1-arm64.apk`。Android 8.0+、ARM64 手机可试用；截图 OCR 需要 Android 11+。
3. 用同页 `SHA256SUMS.txt` 核对文件，`SIGNING-CERT-SHA256.txt` 提供签名证书指纹。
4. 按系统提示安装。GitHub 的 Source code 压缩包是源码；[Actions](https://github.com/NanCC-247/AdCalm/actions/workflows/ci.yml) 的 Debug 包用于开发测试。

Windows 可计算文件校验值：

```powershell
Get-FileHash -Algorithm SHA256 .\AdCalm-v0.1.1-beta.1-arm64.apk
```

如果已有 Debug 包或其他签名版本，系统可能拒绝覆盖安装。先记录自己的设置，并处理需要保留的隔离文件和导出数据，再卸载旧版本、安装 Release；卸载会清除应用私有数据。不要把“清除数据”当作无损升级办法。

## 先观察，再启用

1. 按“两步开启”引导前往系统设置，启用 AdCalm 无障碍服务。
2. 回到应用管理，先选择少量需要处理的应用。选择自动保存，支持搜索、已选筛选和批量操作。
3. 保持默认纯观察，查看实际状态与日志；确认用途后，在首页主动开启自动模式。

新安装默认纯观察且未选择应用。首次升级到本版本也会恢复纯观察，并关闭增强回退、强停、下载处置和无障碍绑定恢复；需要的功能请重新查看说明并确认开启。应用列表与已有数据的保留取决于是否覆盖安装。

部分系统会限制侧载应用启用无障碍；如出现“受限设置”，按系统提示在应用信息页允许相关设置。入口随系统版本与厂商变化。

基础跳过无需 root 或 Shizuku，也不占用 VPN 连接。本机推荐使用本地记录或使用情况作为参考，结果需要确认；推荐不等于已经验证该应用包含可操作广告。

## 增强功能与权限

**授权权限不会替你开启所有功能。** 增强操作默认关闭，开启时分别显示用途及确认提示。按实际需要配置即可。

| 能力或权限 | 用途与边界 |
|---|---|
| 无障碍服务 | 读取页面节点；自动模式下尝试点击界面已有的跳过或关闭按钮。 |
| 使用情况访问 | 辅助使用记录、保护名单与误跳判定。 |
| 增强回退 | 符合判定条件时尝试返回或回到原应用，可能改变前台页面。默认关闭。 |
| 强停 | 符合判定条件时尝试结束目标应用，可能影响其未保存任务。默认关闭，需可用通道。 |
| 通知访问 | 下载处置开启后，在相关条件下尝试取消下载通知中的任务。 |
| 文件访问 | 下载隔离开启后，监控标准下载目录并隔离符合条件的安装包。 |
| Shizuku | 可选通道，用于增强强停、返回原应用、手动扫描清理与无障碍绑定恢复。 |
| 无障碍绑定恢复 | 已有配置失效时尝试通过 Shizuku 恢复。默认关闭，可随时关闭。 |

增强权限未配置时，部分能力会降级或不可用；以应用状态和能力自检结果为准。Shizuku 由外部浏览器前往[官方下载页](https://shizuku.rikka.app/download/)获取，启动与授权方式见[官方项目](https://github.com/RikkaApps/Shizuku)。AdCalm 不内置镜像下载或安装器。

## 自动模式、纯观察与暂停

自动模式在判定条件满足时尝试操作已有按钮，增强功能仍由各自开关控制。本版本要求广告专用文案，或通用关闭文案与同层明确广告标签；部分旧版会点击的按钮将被忽略，覆盖范围可能下降。应用范围、输入法防护和点击冷却可以减少不必要操作，不能完全避免误判。

OCR 路径当前只接受完整广告专用文案，例如“跳过广告”“关闭广告”；单独“跳过”或“关闭”即使位于角落，也不会触发 OCR 自动点击。位置、资源 ID 或倒计时本身不能代替广告关闭证据。

纯观察的识别流程只记录结果，不执行自动点击、回退、强停或新增文件隔离。完整诊断是另一个默认关闭的设置，开启前会说明记录范围。

出现误点时先切回纯观察或暂停保护，再取消相关应用的选择。需要彻底停止系统服务时，在系统设置关闭 AdCalm 无障碍。若不希望尝试恢复绑定，也关闭该增强选项或撤销 Shizuku 授权。

暂停或纯观察后，下载通知处置也受门禁控制。原有隔离文件保持隔离，直到用户恢复或逐项确认永久删除；本版本不按时间自动清理。

## 下载隔离与手动清理

| 操作 | 处理方式 | 是否可恢复 |
|---|---|---|
| 标准下载目录隔离 | 开启后，将符合条件的可疑安装包移入隔离区，保留至用户恢复或逐项确认永久删除。 | 隔离期间可恢复；确认永久删除后不可恢复，不定时自动删除。 |
| 手动安装包清理 | 借助 Shizuku 扫描部分目录中的候选安装包，由用户核对后确认删除。 | 永久删除，不进入隔离区。 |

候选结果不等于已证实的广告下载或无用文件。处理前核对路径与大小，保留正在下载、安装或计划使用的正常文件。暂停处理不会撤销已经完成的文件移动或删除。

## 状态、日志与能力自检

首页显示服务状态、操作统计与最近扫描时间。操作统计记录已发起的点击，不能据此计算真实广告关闭率。

在“设置 → 能力自检”中检查无障碍、前台窗口、截图、OCR、手势及强停通道。权限已授权和能力实际可用是两件事；未知或失败结果应结合页面原因排查。

日志导出脱敏摘要，公开反馈优先使用该摘要和复现步骤。完整诊断只记录所选应用的界面内容，仍可能包含私人信息，应短时开启、复现后关闭，原始文件留在本机。“清空日志”同时清理诊断截图和应用生成的本机导出文件，自行另存或已分享的副本需另外管理。详细数据范围见[隐私说明](../privacy.md)。

## 常见问题

**没有自动跳过**

依次检查：应用是否已选、无障碍是否实际运行、是否仍为纯观察、能力自检是否通过。通用关闭按钮没有同层明确广告标签时会被忽略；无文字或缺可靠节点的关闭按钮也可能无法识别。Android 8–10 没有截图 OCR 兜底。

**运行一段时间后失效**

检查实际无障碍状态和厂商后台限制。不同 ROM 的后台管理与省电设置不同。可选的无障碍绑定恢复依赖 Shizuku，也不能保证服务持续运行。

**出现误点或误回退**

先暂停、恢复纯观察或取消该应用的选择，再记录场景与复现步骤。通过 [问题模板](https://github.com/NanCC-247/AdCalm/issues/new/choose)提交版本、系统、模式和相关开关；没有日志也可以反馈。建议同一时间只使用一个会自动操作此类界面的工具，避免重复动作。

**需要其他架构或自行构建**

按[开发指南](开发指南.md)调整构建并验证原生 OCR 依赖与安装兼容性。
