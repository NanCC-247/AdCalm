# AdCalm 开发指南

## 环境

| 项目 | 要求 |
|---|---|
| JDK | 17 或更高，源码兼容级别为 17。 |
| Android SDK | Android 35 平台与对应构建工具。 |
| Gradle | 使用仓库自带 Wrapper，无需额外安装。 |
| 默认目标 | Android 8.0+、ARM64。截图 OCR 需要 Android 11+。 |

推荐使用 Android Studio 打开项目并配置 SDK，或通过 `ANDROID_HOME` / 项目内 `local.properties` 指定 SDK。工具链和个人配置不随仓库分发。

## 构建与检查

Linux、macOS 或 Git Bash：

```bash
./gradlew assembleDebug
./gradlew testDebugUnitTest
./gradlew lintDebug
```

Windows PowerShell：

```powershell
.\gradlew.bat assembleDebug
.\gradlew.bat testDebugUnitTest
.\gradlew.bat lintDebug
```

也可使用 `./build.sh`，由 `env.sh` 优先定位本机或项目内工具链。默认产物为 `app/build/outputs/apk/debug/app-debug.apk`，属于测试构建。

源码路径含非 ASCII 字符时，项目会将产物重定向到同级 `adcalm-build/`。为减少工具链路径问题，建议克隆到纯 ASCII 路径；本机具体目录不属于仓库要求。

## 设备测试与架构

默认仅打包 `arm64-v8a`。x86_64 模拟器测试可添加：

```bash
./gradlew connectedDebugAndroidTest -PwithEmulatorAbi
```

仪器测试会安装测试包，并可能卸载或影响测试设备上的本应用数据，建议使用专用设备或模拟器。需要其他架构时，先调整 `app/build.gradle.kts` 的 `abiFilters`，再验证 OCR 原生依赖和安装兼容性。

CI 执行 JVM 单测、Android Lint 和 Debug 装配，设备测试需另行运行。成功的 CI 运行会上传临时 Debug 构建产物，在 [Actions](https://github.com/NanCC-247/AdCalm/actions/workflows/ci.yml) 的对应运行中查看 Artifacts，下载需登录 GitHub，保留期为 30 天。此产物是测试包，与 Release 附件和正式签名发布不同。单测结果不等于真实广告成功率、ROM 覆盖率或耗电测量。

## 源码结构

源码根目录为 `app/src/main/java/cn/adcalm/guard/`。

| 目录 | 职责 |
|---|---|
| `model/` | 节点、候选与区域等数据模型。 |
| `core/` | 识别评分、动作防护、扫描调度及系统能力相关组件。 |
| `rules/` | 规则模型、匹配与资源加载。 |
| `ocr/` | 本机文字识别与截图封装。 |
| `service/` | 无障碍事件、识别执行、下载通知处理。 |
| `shizuku/` | 可选 shell 通道、安装与状态检查。 |
| `data/` | 日志、隔离区与安装包扫描。 |
| `ui/` | 首页、应用管理、权限、自检及其他原生页面。 |

可独立测试的判定逻辑接收纯数据，Android 系统交互由相关组件负责。`core/` 按职责组织，包含系统相关代码，不能将整个目录视为纯函数库。

## 规则与回归

默认内置规则列表为空，当前识别主要依赖启发式节点判断与 OCR。规则框架存在，不代表已有用户可用的订阅或编辑器。

调整识别时，应提供可复现样本，并验证正常页面负样本、输入法、界面切换与重复点击场景。文件处置需分别验证隔离恢复和用户确认删除。
